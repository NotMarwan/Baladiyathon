# تدقيق اشتقاق `workZoneFriction`

> أُعيد بناء الاشتقاق من المصادر الأصلية ومن الشيفرة، دون الاعتماد على تفسير
> الوكيل السابق.

## 1. التعريف الرياضي — كما يستعمله المحرك فعلاً

`presentation/athar-engine.js:369-374`:

```js
const baseT   = bprTravelTime(freeFlowMin, demand, fullCapacity);
const closedT = lanesClosed > 0
  ? Math.max(
      bprTravelTime(freeFlowMin, demand, closedCapacity),
      baseT * CAL.workZoneFriction,          // ← هنا
    )
  : baseT;
```

ومعه:

```js
function bprTravelTime(freeFlowMin, volume, capacity) {
  const ratio = volume / capacity;
  return freeFlowMin * (1 + 0.15 * Math.pow(ratio, 4));   // BPR، β = 4
}
```

| السؤال | الجواب |
|---|---|
| الوحدة | **بلا أبعاد** — نسبة زمن إلى زمن |
| هل هو معامل سعة؟ | **لا.** السعة تدخل عبر `closedCapacity` في حدٍّ منفصل |
| هل هو معامل زمن؟ | **نعم** — يضرب `baseT` |
| هل هو معامل تأخير؟ | **لا مباشرة** — التأخير مشتقّ لاحقاً من `closedT - baseT` |
| ما دوره الدقيق؟ | **أرضية (floor)** على نسبة `closedT / baseT` |

**الترجمة اللفظية الدقيقة:** «زمن العبور أثناء الإغلاق لا يقلّ أبداً عن
`friction` × زمن العبور بلا إغلاق — أياً كان الطلب.»

هذا يطابق التعليق الأصلي في `athar-prototype.html:1974`:
«أرضية: زمن الإغلاق ≥ 110٪ من الأساس — يمنع تصفير تأخير الليل».

## 2. القيم المرجعية الثلاث

| القيمة | المصدر | السياق | الوحدة | ما هي فعلاً؟ |
|---:|---|---|---|---|
| **1072** | `missouri-breakdown` — أرشيف كواشف، ميزوري | طريق **سريع** (freeway) | مركبة/ساعة/حارة | **معدّل تصريف الرتل** بعد الانهيار — أي تدفق تحت التشبّع لا سعة قصوى |
| **1600** | `tti-1108-5` — TTI للإدارة الفيدرالية | طريق **سريع**، إغلاق حارة قصير الأمد | مركبة-ركّاب/ساعة/حارة | **سعة أساس موصى بها للتصميم** (pcphpl، لا vph) |
| **1800** | `athar-engine.js:36` | افتراض داخلي | مركبة/ساعة/حارة | **تدفق التشبّع** خارج منطقة العمل — موسوم في الشيفرة «افتراض توضيحي للعرض» |

### قابلية المقارنة بين الثلاث — ضعيفة، والسجل يعرف ذلك

- **1072 مقابل 1600**: كميتان مختلفتان (تصريف رتل مقابل سعة تصميمية)، لا
  طرفَي نطاق لكمية واحدة.
- **pcphpl مقابل vph**: `1600` بوحدة مركبة-**ركّاب**، و`1072` و`1800` بمركبة
  خام. التحويل بينهما يحتاج عامل مركبات ثقيلة، وهو غير مطبَّق.
- **freeway مقابل شريان حضري بإشارات**: كل المصادر الرقمية من طرق سريعة،
  ومحفظة أثر شرايين حضرية. السجل يقولها بنفسه («القيمة تصلح حدّاً أعلى لا
  قيمةً منقولة»)، وأقرب دراسة نوعياً (Delaware — شريان متعدد الحارات بإشارات)
  مسجَّلة `context-only` و«معلَّق — يحتاج قراءة يدوية». أي أن **أهم مصدر لم
  يُقرأ**، وهذا معلَن لا مخفي.
- `method-comparison-field` يثبت أن **طريقة القياس** تحرّك الرقم 274 وحدة —
  أكثر مما يحرّكه الموقع. وهذا وحده يمنع جمع دراسات مختلفة الطرائق في نطاق واحد.

**تسجيل هذه القيود في السجل نفسه إنجاز حقيقي.** المشكلة ليست في الشفافية،
بل فيما بُني فوقها.

## 3. إعادة إنتاج النطاق حسابياً

`athar-sensitivity.js:177-183`:

```js
range: function () {
  var base = Engine.DEFAULTS.capacityPerLane;          // 1800
  return {
    low:  Math.round((base / frictionPrior.priorHigh) * 100) / 100,   // 1800/1600
    high: Math.round((base / frictionPrior.priorLow)  * 100) / 100,   // 1800/1072
  };
}
```

تشغيل مستقل:

```
computed range: {"low":1.13,"high":1.68}
1800/1600 = 1.125          → Math.round(112.5)/100 = 1.13
1800/1072 = 1.6791044776…  → Math.round(167.91)/100 = 1.68
```

**النطاق `[1.13 – 1.68]` أُعيد إنتاجه بالضبط.** الادعاء العاشر صحيح عددياً.

### تعارض نصّي — F5

`data/comparable-cases.json` يقول في `consequenceForAthar`:

> «…أي أن مضاعِف الاحتكاك يقع بين **1.12** و1.68»

والشيفرة تحسب **1.13** (لأن `Math.round(112.5) = 113` في JavaScript). فارق
0.01 بين النصّ الحاكم والقيمة المنفَّذة. صغير، لكنه في ملف يُقرأ مصدراً.

## 4. الفحص البُعدي — هنا يسقط الاشتقاق

النطاق مشتقّ هكذا: **نسبة سعة** داخل منطقة العمل إلى خارجها = `1072/1800 = 0.60`
إلى `1600/1800 = 0.89`، ثم **مقلوبها** = `1.13` إلى `1.68`.

ثم يُستعمل الناتج **أرضيةً على نسبة زمن**.

**هاتان كميتان مختلفتان، والفرق بينهما ليس صغيراً.**

تحت BPR، إذا انخفضت السعة بعامل `r`، فإن نسبة الزمن تساوي:

```
t_closed / t_base = (1 + 0.15·(v/(r·c))⁴) / (1 + 0.15·(v/c)⁴)
```

وهي **ليست** `1/r`. حساب مستقل على مقطع من 4 مسارات (إغلاق واحد، `r = 0.75`):

| `v/c` الأساسي | نسبة الزمن الفعلية من BPR | `1/r` (منطق الاشتقاق) |
|---:|---:|---:|
| 0.2 | **1.001** | 1.500 |
| 0.4 | **1.016** | 1.500 |
| 0.6 | **1.077** | 1.500 |
| 0.8 | **1.235** | 1.500 |
| 1.0 | **1.530** | 1.500 |

نسبة الزمن الحقيقية تتراوح من 1.001 إلى 1.53 حسب الطلب. ومقلوب نسبة السعة
**ثابت**. المطابقة عند `v/c = 1.0` مصادفة عددية لا تكافؤ.

### الأثر العملي للخطأ

المعامل أرضية، فهو يُلزِم **كل ساعة** بحدٍّ أدنى من الزيادة الزمنية:

```
عند v/c = 0.2:   BPR closed/base = 1.0010
                 أرضية 1.10 ⇒ 1.100   (أثر مخترَع بنسبة 10٪)
                 أرضية 1.68 ⇒ 1.680   (أثر مخترَع بنسبة 68٪)
```

أي أن رفع الطرف الأعلى إلى 1.68 يعني: **عند الثالثة فجراً على شارع شبه خالٍ،
يفترض النموذج أن الإغلاق يزيد زمن العبور 68٪** — بينما منحنى BPR الذي يستعمله
النموذج نفسه يقول 0.1٪. والقيمة 1.68 مشتقّة من دراسات **سعة** لا تقيّد شيئاً
عند طلب منخفض؛ قيد السعة لا يعمل إلا قرب التشبّع.

الاتجاه صحيح (أكبر = أسوأ)، والبسط والمقام غير مقلوبين (سعة أقل ⇒ معامل أعلى ✅).
والعيب في **الكمية نفسها**: ثلاثة تعريفات (تصريف رتل، سعة تصميمية، تدفق تشبّع)
جُمعت في نسبة واحدة، ثم نُقلت النسبة من فضاء السعة إلى فضاء الزمن بلا جسر.

## 5. عيب ثانٍ — نقطة التشغيل خارج نطاقها

```
engine default WORK_ZONE_FRICTION : 1.10
evidence-derived range            : [1.13 – 1.68]
base inside range?                : false
```

`athar-engine.js:102` ما زال `WORK_ZONE_FRICTION = 1.10`، وهي **أدنى من أدنى
قيمة يسندها دليل المشروع نفسه**.

النتيجة: كل رقم أثر معروض في الواجهة (مثل `18,994 ساعة-مركبة` على
BLD-2026-0045) محسوب عند نقطة صنّفها المشروع نفسه **غير مسنودة وأكثر تفاؤلاً
من الدليل**. وتحليل الحساسية يمسح `[1.13 – 1.68]`، فالرقم المعروض يقع **خارج
الشريط** الذي تعرضه الأداة حوله.

الوكيل قال «توسيع النطاق يزيد الهشاشة ولا ينقصها» — صحيح، لكن التوسيع طُبّق
على **النطاق** ولم يُطبَّق على **النقطة**. نصف الإصلاح.

## 6. الحكم

> **The revised friction range is not independently defensible** as a floor on
> the travel-time ratio.

بالتفصيل:

| الوجه | الحكم |
|---|---|
| الحساب `1800/1600` و`1800/1072` | ✅ أُعيد إنتاجه بالضبط |
| المصادر (1072 · 1600) | ✅ حقيقية، منسوبة، ومقروءة بأمانة مع قيودها |
| الاتجاه | ✅ صحيح |
| ترتيب البسط/المقام | ✅ صحيح |
| الاتساق البُعدي | ❌ **يسقط** — نسبة سعة تُستعمل نسبةَ زمن |
| خلط ثلاثة تعريفات | ❌ **نعم** — تصريف رتل + سعة تصميمية + تدفق تشبّع |
| مطابقة طريقة الاستعمال داخل المحرك | ❌ **لا** — القيد سعوي، والاستعمال أرضية زمنية عند كل مستويات الطلب |
| نقطة التشغيل داخل النطاق | ❌ **لا** — 1.10 خارج `[1.13 – 1.68]` |

**النطاق `[1.13 – 1.68]` صالح بوصفه أولوية سعة (`0.60 – 0.89` من السعة)،
وغير صالح بوصفه نطاق مضاعِف زمن.**

**ولا يُعتبر قيمة حاكمة.** والمخفِّف الحقيقي: المصنِّف يصنّف كل حالة يقلبها
هذا المعامل امتناعاً، وهذا المعامل هو أول ما يقلب — فالنظام يمتنع بدل أن
يقرّر على أساس فاسد. الامتناع يحمي المستخدم من العيب، لكنه لا يصلحه.
