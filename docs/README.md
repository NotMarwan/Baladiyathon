# فهرس التوثيق

سبعة مجلدات، كل واحد بغرض واحد. لا ملفات سائبة في جذر `docs/`.

## `hackathon/` — المرجع الحاكم

ما تُحاكَم عليه المشاركة. ابدأ من هنا قبل أي قرار منتج.

| الملف | الدور |
|---|---|
| `المرجع-الرسمي-للهاكاثون.md` | المعايير الستة الرسمية، التواريخ، الجوائز |
| `معايير-التقييم-الصارمة.md` | الرُبرِك الداخلي — الهدف ≥ ٩٫٥/١٠ لكل معيار |
| `بطاقة-الفكرة.md` | بطاقة الفكرة المُقدَّمة. اختبارات `presentation/tests/` تقرأها وتحرسها |
| `اجوبة-الفورم.md` | نص التقديم الرسمي حرفياً. أول ما تقرؤه اللجنة — تحرسه `pitch-integrity-test.js` |

## `evaluation/` — نتائج التحكيم

التحكيم البارد، تقارير المعايير، التقييم الصارم النهائي. مرتّبة زمنياً بالاسم؛ الأحدث `COLD-JUDGING-2026-07-27.md`.

## `policy/` — قرارات ملزِمة

`DIGONCE-COMPLIANCE-POLICY.md` و`-SUMMARY.md` (يحرسهما `digonce-compliance-test.js`)، `FLOOR-DECISION-2026-07-26.md`، `MERGE-PLAN.md`.

## `engineering/` — سلوك النظام

`STABILITY.md`، `FEASIBILITY.md`، `SHADOW-PILOT.md` (بروتوكول التقييم الظلّي — ترتبط به صفحات العرض)، `WZDX-CONFORMANCE.md`، `WZDX-INTEROP.md`، `FLAKY-SERVER-SUITES-2026-07-26.md`، `HOW-IT-WORKS.md` (بنية سرب الوكلاء الأربعة).

## `audits/` · `plans/` · `superpowers/`

التدقيقات المستقلة، خطط التحسين، وخطط التنفيذ التفصيلية. سجلّ عمل — اقرأ منها عند تتبّع «لماذا اتُّخذ هذا القرار»، لا عند بناء ميزة جديدة.

---

**قاعدة الروابط:** أي ملف هنا يُشار إليه من كود أو اختبار يجب ألّا يُنقل دون تحديث المرجع وتشغيل `npm test`. المسارات المرتبطة حالياً بالكود: `hackathon/بطاقة-الفكرة.md`، `hackathon/اجوبة-الفورم.md`، `policy/DIGONCE-COMPLIANCE-*.md`، `audits/AUDIT-2026-07-25.md`، `engineering/SHADOW-PILOT.md`.
