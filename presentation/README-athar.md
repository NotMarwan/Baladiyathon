# أثر — دليل التشغيل السريع

## ⚡ دليل المحكّم — 60 ثانية

1. افتح `presentation/athar-prototype.html`.
2. اضغط «حدد موقع الحفر» ثم «حسّن الجدولة».
3. اختر الجدول الأول وشاهد الأحمر يتحول أخضر والعدّادات.
4. اضغط «أصدر خطة إدارة المرور PDF».

وضع API (اختياري، لخادم Node محلي بدون تبعيات): شغّل `node presentation/server.js`
ثم افتح `http://localhost:8734/athar-prototype.html`. الاختبارات: `node presentation/tests/engine-test.js`.

نموذج تفاعلي لتقييم الأثر المروري لتصاريح الحفر، وجدولة مثلى، ودمج تصاريح
(Dig-Once)، ضمن مبادرة **بلدياتثون 2026 · التحدي الثالث**.

## (أ) الوضع الثابت (بدون خادم)

افتح الملف مباشرة في المتصفح:

```
presentation/athar-prototype.html
```

يعمل النموذج بالكامل بدون اتصال بالإنترنت باستثناء بلاط الخريطة (OSM
tiles). في حال تعذّر تحميل البلاط تبقى الخريطة بخلفية رمادية وتستمر جميع
البطاقات والحسابات بالعمل بلا أي أخطاء في الـ console.

## (ب) وضع الـ API (خادم محلي)

```bash
node presentation/server.js
```

ثم افتح:

```
http://localhost:8734/athar-prototype.html
```

تكتشف الصفحة الخادم تلقائيًا (فحص `fetch('/api/works')` بمهلة 800ms) وتعرض
شارة «متصل بالخادم — وضع API»، وتوجّه طلبات الدرجة/الجدولة المثلى عبر
الـ API بدلًا من حساب المحرك محليًا.

### نقاط النهاية (Endpoints)

| المسار | الطريقة | الوصف |
|---|---|---|
| `/api/score` | POST | حساب درجة الأثر المروري لإغلاق مسارات معيّن |
| `/api/optimize` | POST | أفضل 3 جداول زمنية بديلة |
| `/api/digonce` | POST | مقارنة تكلفة الحفر المنفصل مقابل الحفر المشترك |
| `/api/works` | GET | خريطة الأعمال العامة (GeoJSON) |

الخادم يعتمد فقط على مكتبات Node القياسية (`http`, `fs`, `path`, `url`) —
بلا أي تبعيات خارجية.

## (ج) الاختبارات

```bash
node presentation/tests/engine-test.js
```

يطبع `ALL TESTS PASSED (n)` عند النجاح، أو يرمي خطأ فوري عند أي فشل. يغطي
كل حالات السلامة العددية المطلوبة (إغلاق ليلي أقل تأثيرًا من نهاري، تصاعد
التأخير مع عدد المسارات المغلقة، سقف السعة عند إغلاق كل المسارات، لف
الساعات عند مدة تتجاوز 24 ساعة، صفر تأخير عند صفر مسارات مغلقة، ونطاق
Dig-Once المعاير).

## (د) بنية الملفات

```
presentation/
├── athar-engine.js        # المحرك الحسابي الصِرف (المصدر الوحيد للحقيقة)
├── server.js               # خادم Node stdlib + واجهات API
├── athar-prototype.html    # النموذج التفاعلي (الخطوات السبع)
├── athar-pitch.html        # عرض الملعب (3 دقائق)
├── athar-merged.html       # نسخة التصميم المرجعية (design tokens)
├── data/
│   └── works.geojson       # خريطة الأعمال العامة (بيانات توضيحية)
├── vendor/
│   ├── leaflet.js
│   └── leaflet.css
├── tests/
│   └── engine-test.js      # اختبارات node:assert
└── README-athar.md         # هذا الملف
```

## ملاحظة مصادر البيانات

كل رقم واقعي معروض في الواجهة أو العرض يحمل مصدرًا من سجل المصادر
(Sources Ledger). أي مُدخل تجريبي (مثل حجم المرور الافتراضي) يُعلَّم
بوضوح بعبارة «بيانات توضيحية للعرض».
