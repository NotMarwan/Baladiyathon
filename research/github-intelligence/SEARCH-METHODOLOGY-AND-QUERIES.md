# منهج البحث والاستعلامات

## نقطة البداية

بُني سجل احتياج القدرات أولاً من الكود وخطة التحسين والبحث التنافسي. لم تستخدم النجوم في التقييم، واستعملت فقط لاكتشاف مشاريع بديلة.

## مصادر الفحص

- بحث المستودعات العام.
- موضوعات المستودعات.
- قوائم جغرافية موثوقة.
- مستودعات حكومية أمريكية لمعيار مناطق العمل.
- مؤسسات المشاريع الأصلية.
- سجل الحزم العام للإصدارات والاعتماديات وسلامة الحزم.
- واجهة الثغرات المفتوحة.
- المشكلات وطلبات الدمج والإصدارات الحديثة.
- ملفات الرخص الأصلية.
- تشغيل معزول خارج المشروع.

## الجولات

### الجولة الأولى

غطت الخرائط، والفهارس، والتوجيه، ومناطق العمل، والتحقق، وأمن خادم نود.

استعلامات نموذجية:

```text
geospatial spatial index GeoJSON
PMTiles vector tiles MapLibre
OSM routing turn restrictions map matching
WZDx work zone data exchange
Node JSON Schema validation OpenAPI
Node HTTP security rate limit audit
```

أعيد ثمانية وأربعون صفاً. بعد حذف القوائم العامة والنتائج غير المتعلقة بقيت الفئات الأساسية نفسها التي حددها سجل الاحتياج.

### الجولة الثانية

بحثت بأسماء الأنظمة البيئية والبدائل المنافسة:

```text
rbush flatbush kdbush geojson-vt supercluster
Valhalla OSRM openrouteservice GraphHopper
fast-check Playwright axe pixelmatch
XState JSON rules Casbin audit log
SUMO MATSim UXsim CityFlow
OpenLineage Great Expectations provenance
HTML PDF report generation
```

فُحص تسعة وثلاثون صفاً مادياً. ظهرت بدائل داخل الفئات، ولم تظهر قدرة جديدة تستحق تغيير سجل الاحتياج.

### الجولة الثالثة

استخدمت موضوعات مباشرة:

```text
topic:spatial-index language:JavaScript
topic:json-schema language:JavaScript
topic:property-based-testing language:TypeScript
topic:routing-engine openstreetmap
topic:traffic-simulation
work-zone road-closure schema
```

فُحص أربعون صفاً. لم يتغير القرار: فهرس صغير، مخطط رسمي، وأدوات تحقق، مع إبقاء المحركات الكبيرة خارج المنتج.

### الجولة الرابعة

فحصت الفئات المجاورة:

```text
topic:vector-tiles language:JavaScript
topic:map-matching openstreetmap
topic:data-quality framework
topic:workflow-engine language:TypeScript
topic:accessibility-testing JavaScript
topic:sbom license scanner
```

أضافت الجولة أمثلة مثل سير العمل المتين وخوادم البلاطات، لكنها لم تغير قراراً. كانت منصات أكبر من الحاجة أو تكرر مرشحاً أخف.

## حجم الفحص

- مئة وسبعة وعشرون صف بحث من الجولات الأربع.
- ستة وثمانون مستودعاً فريداً بعد إزالة التكرار.
- اثنان وأربعون مستودعاً فُحصت بياناته الوصفية ورخصته وحالته.
- ثمانية عشر مرشحاً فُحص إصدارهم الأخير ونشاطهم ومخاطرهم.
- ثلاثة عشر مرشحاً فُحصت جودة المجتمع والاختبارات والتكامل المستمر.
- ست حزم شُغلت أو استوردت في بيئة معزولة.

## معيار التشبع

اعتُبر البحث مشبعاً لأن الجولات الثانية والثالثة والرابعة لم تضف فئة حل تغير قرار الاستخدام. كما توفر لكل قدرة مهمة ثلاثة بدائل أو ثبت انفراد معيار رسمي واحد، كما في مخطط مناطق العمل.

## أسباب الاستبعاد أثناء البحث

- قائمة روابط بلا مكون قابل للاستخدام.
- تطبيق كامل لحاجة مكتبة صغيرة.
- مشروع مؤرشف وله بديل نشط.
- رخصة غائبة أو غير واضحة.
- تطابق اسمي بلا تغطية للحاجة الفعلية.
- اعتماد على خدمة مغلقة أو بيانات غير متاحة.
- منصة تتطلب قاعدة بيانات أو فريق تشغيل.
- مشروع أكاديمي أو تجريبي يعرض كحل إنتاجي.
- نتيجة قديمة استبدلت بمستودع رئيسي أحدث.

## التحقق العملي

أُنشئت بيئة مؤقتة خارج المشروع، وثبتت الحزم مع تعطيل سكربتات التثبيت، ثم شُغلت الاختبارات التالية:

- مقارنة فهرسين على مئة ألف صندوق وألف استعلام.
- تبليط عشرين ألف نقطة.
- قراءة أرشيف بلاطات رسمي عبر طلبات نطاق.
- تحقق حدود مدخلات الخادم.
- تحقق التصدير الحالي مقابل المخطط الرسمي.
- ألف حالة خصائص لمحرك الأثر.
- فحص ثغرات لشجرة الاعتماديات المعزولة.

لم تُعدّل ملفات المنتج، ولم تُضف اعتمادية إلى المشروع.
