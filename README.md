# مسار (Masar) — بلدياثون 2026، التحدي الثالث

تقييم أثر الحفريات على الحركة المرورية **قبل** إصدار التصريح، وجدولة الأعمال، وتنسيق الحفر الموحّد (dig-once).

> **اسم المشروع هو «مسار».** أي ملف يسمّيه «أثر» فهو من مرحلة سابقة ومكانه `_archive/athar-era/`. لا تبنِ عليه.

---

## وكيل جديد؟ اقرأ هذه الخمسة وتوقّف

بهذا الترتيب. لا تفتح شيئاً سادساً قبل أن تعرف ماذا تبحث عنه.

| # | اقرأ | تخرج منه بـ |
|---|---|---|
| ١ | هذا الملف حتى نهايته | الهيكل، ما هو حيّ وما هو ميت، أمر التشغيل |
| ٢ | [`AGENTS.md`](AGENTS.md) | الممنوعات، قاعدة الأدلة، بوابة القبول |
| ٣ | `graphify query "<سؤالك>"` | أسماء الملفات المتعلّقة بمهمتك تحديداً — **اقرأ التحذير أسفله أولاً** |
| ٤ | الملفات التي سمّاها الرسم — وحدها | السياق الفعلي لمهمتك |
| ٥ | `SwarmingObsidian/01 Masar/Masar - Master.md` عند الحاجة لمواصفة المنتج | التعريف الكامل للنظام |

**ثم ابدأ العمل.** `grep` أداة تحقّق لا أداة استكشاف — استخدمها بعد أن يدلّك الرسم، لا قبله.

> **الرسم أُعيد بناؤه (٢٨ يوليو ٢٠٢٦) و`_archive/` مستثنى منه** عبر `.graphifyignore` في الجذر — فمفاهيم الحقبة الميتة (NADHEER، BASEERA، «Challenge 1»، عقد `athar-*`) لم تعد عقد تنقّل. ويبقى أدب التعامل: نتيجة `graphify query` اقتراحُ موضعٍ لا مصدرُ حقيقة — تحقّق أن الملف موجود قبل البناء عليه. وملف الاستثناء في **الجذر** عن قصد: graphify يقرأ ملفات التجاهل من أسلاف جذر المسح وحدها، وملفٌ داخل `_archive/` نفسه لا يُقرأ (جُرِّب وقيس).

ثلاثة أخطاء يقع فيها كل وكيل جديد هنا:

1. **قراءة `_archive/`.** محتواه أفكار مُقصاة وتصاميم مُستبدَلة. يبدو مقنعاً ويقود لقرار مبني على واقع منتهٍ.
2. **البحث عن ملف `athar-*`.** لا يوجد. المشروع أُعيدت تسميته إلى «مسار» وكل ملفات النموذج `masar-*`.
3. **قياس خط أساس في شجرة عمل جديدة قبل نسخ `node_modules`.** تسقط حزمتان بـ `Cannot find module 'ajv'` فيظنّها الوكيل انحداراً. الأمر: `cp -r Baladiyathon/node_modules <worktree>/`

## تشغيل في ٦٠ ثانية

```bash
node presentation/server.js
```

ثم افتح `http://localhost:8734/`. نقطة الدخول للمحكّم: **مكتب المراجع** — ١٥٠ تصريحاً على شوارع رياض حقيقية.

```bash
npm test
```

٧٧ حزمة · ١٢٧٨ فحصاً. هذه بوابة القبول: أي تغيير يجب أن يبقيها خضراء.

## قواعد التنقل للوكلاء

**١. الرسم أولاً، نظام الملفات ثانياً.**

```bash
graphify query "كيف يحسب مسار درجة التأثير المروري؟"   # جواب مع المصادر
graphify path "Masar" "SUMO"                            # أقصر مسار بين مفهومين
graphify explain "BPR Score"                            # شرح عقدة
graphify update                                         # إعادة الفهرسة بعد التعديل
```

اسأل الرسم لتحديد المجتمع والملفات، ثم افتح تلك الملفات وحدها. لا تمشِ في الشجرة عشوائياً.

**٢. لا تقرأ `_archive/`.** محتواه أفكار مُقصاة وتصاميم استُبدلت وتقييمات من مرحلة «أثر». قراءته تنتج قرارات مبنية على واقع منتهٍ.

**٣. الحساب له مصدر واحد.** كل رقم مروري يخرج من `presentation/masar-engine.js`. لا تُعِد اشتقاق معادلة في مكان آخر.

**٤. قاعدة الدليل.** صنّف كل رقم: مُثبَت عملياً، مُتحقَّق خارجياً، متوقَّع من تجربة، أو سيناريو توسّع مشروط. الادعاء بلا مصدر يُخصم في التحكيم.
